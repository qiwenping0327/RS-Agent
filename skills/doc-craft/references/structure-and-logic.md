# 结构与逻辑指南

## 1. 金字塔原理（全文骨架）

```
            ┌─────────────┐
            │   核心结论   │   ← 摘要：一句话回答"文档要论证什么、结论是什么"
            └──────┬──────┘
       ┌───────────┼───────────┐
   ┌───┴───┐   ┌───┴───┐   ┌───┴───┐
   │ 分论点1 │   │ 分论点2 │   │ 分论点3 │   ← 各章：独立支撑核心结论
   └───┬───┘   └───┬───┘   └───┬───┘
     论据组      论据组      论据组        ← 数据/案例/文献
```

- 自上而下表达：先结论，后论据。
- 自下而上思考：收集完资料后，先归类论据 → 提炼分论点 → 归纳核心结论。
- 每一章第一段必须能独立回答："这一章的结论是什么？"

## 2. MECE 章节自检

大纲完成后逐项检查：
- **不重叠**：两个章节是否在讲同一件事的不同侧面？是 → 合并或切分视角。
- **不遗漏**：核心问题的各要素是否都覆盖？（如市场分析 = 供给 + 需求 + 竞争格局 + 政策）
- **有递进**：章节顺序是否符合读者认知路径（背景 → 现状 → 分析 → 方案 → 结论）？

## 3. 段落写法（观点—论据—例证—小结）

反例（伪深度）：
> 区块链技术具有重要意义。它去中心化、不可篡改，在很多行业都有广泛应用，未来前景十分广阔。

正例（有论据链）：
> 区块链的不可篡改性使其适合存证类场景。以司法存证为例，杭州互联网法院自 2018 年
> 接入司法区块链后，电子证据认定的平均周期从约 30 天缩短至即时核验 [1]。
> 这说明：当"信任成本"是行业主要摩擦点时，区块链具备落地价值；反之则易沦为概念包装。

拆解：观点（适合存证）→ 论据（司法案例 + 量化数据）→ 引用（[1]）→ 边界（"当…时"给出适用条件，避免绝对化）。

## 4. 深度分层框架

每个关键主题至少走完三层，才允许进入下一个主题：

| 层次 | 回答的问题 | 常用手法 |
|---|---|---|
| 是什么 | 概念界定、现状描述 | 定义 + 数据 + 分类表格 |
| 为什么 | 成因、驱动因素、影响机制 | 因果链分析、多方观点对比 |
| 怎么办 / 意味着什么 | 对策、趋势、对读者的行动含义 | 方案对比表、场景推演 |

跨层提示语可用："上述现象背后的驱动因素有三个""这对 XX 的含义在于"。

## 5. 数据与图表规范

- 对比类信息一律用表格；时间演化类可用 Markdown 表格 + 文字描述趋势。
- 表格规范：有编号有标题（"表 2：2023–2025 年国内遥感市场规模对比"），来源注在表下方。
- 数字规范：保留有效位数一致；同列单位统一；大数用"亿/万"中文单位或千分位。
- 引用数据必须带年份和口径（"2024 年，按营收口径"）。

## 6. 语言风格

- 客观语态：多用"数据显示/案例表明"，少用"我认为"。
- 精确动词：用"提升、收敛、挤出、验证"替代"改善、变化"等模糊词。
- 删除冗词：扫一遍删掉"非常、十分、可以说、值得注意的是"（除非真值得注意）。
- 中英混排：中文与英文/数字之间加空格；专有名词首字母大写规范统一。
