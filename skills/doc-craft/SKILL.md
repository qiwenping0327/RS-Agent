# doc-craft — 高质量文档写作

## 核心理念

1. **结论先行**——金字塔原理：每章开头先给结论，再用论据展开；全文先给摘要，再展开正文。
2. **论据可溯源**——关键论断必须有出处（数据、文献、官方文件、可验证链接），绝不编造。
3. **深度分层**——每个主题按"是什么 → 为什么 → 怎么做/意味着什么"三层展开，不停留在现象罗列。
4. **结构即逻辑**——章节之间是递进或并列关系（MECE 不重叠不遗漏），读者看目录就能看懂论证路线。

## 写作工作流（按顺序执行）

### 第 1 步：需求澄清
开始写作前，明确 5 个问题（信息不足时先问用户，不要臆测）：
- **读者是谁**（决策者 / 技术人员 / 公众）——决定语言深浅与详略
- **文档类型**（见路由表）——决定骨架模板
- **篇幅预期**（约多少字 / 多少页）
- **已有材料**（用户提供的资料、数据、既定结论）
- **硬性要求**（指定格式、指定章节、截止用途如汇报/评审/发表）

### 第 2 步：资料收集与事实核查
- 使用可用的搜索/检索工具收集权威来源；无检索工具时，明确告诉用户哪些内容基于模型已有知识、需人工核实。
- 按"可信度分级"取舍来源（见 references/citation-standards.md 第 1 节）。
- 每条将引用的资料记录：来源、时间、关键数据/结论、链接或出处。

### 第 3 步：大纲设计（先出大纲，经确认后展开）
- 用对应文档类型模板搭骨架（见 references/doc-templates.md）。
- 大纲写到二级标题，每个二级标题后用一句话注明"本节要说什么、用什么论据"。
- 大纲自检：章节是否 MECE？逻辑主线是否一句话讲得清？摘要-结论是否呼应？
- 篇幅 3000 字以上的文档，先把大纲给用户确认，再进入分节写作。

### 第 4 步：分节深写
每节按"观点—论据—例证—小结"结构：
- **观点**：本节核心论断，放开头。
- **论据**：数据、对比、案例、文献；优先量化表述（"增长 23%"而非"大幅增长"）。
- **例证**：具体案例或表格（对比信息一律用表格，不用长段落罗列）。
- **小结**：一句话收束，衔接下一节。
- 避免的写法：车轱辘话、空洞形容词堆砌、无来源的绝对化断言、单句成段的伪深度。

### 第 5 步：引用回填
- 文内标注 + 文末参考文献列表，格式见 references/citation-standards.md。
- 每条参考文献都能对应到正文至少一处标注；正文标注都能在文末找到条目。

### 第 6 步：定稿自查
逐项过 references/quality-checklist.md 的交付清单，全部通过才交付。

## 路由表

| 文档类型 | 使用的模板 | 附加要求 |
|---|---|---|
| 研究报告 / 行业分析 | 模板 A（references/doc-templates.md） | 必须有数据图表或对比表格 |
| 技术方案 / 架构设计 | 模板 B | 必须有权衡对比（选型理由、备选方案） |
| 调研 / 评估报告 | 模板 C | 必须有评估维度与方法说明 |
| 综述 / 白皮书 | 模板 D | 必须有发展脉络梳理与趋势判断 |
| 学术风格写作 | 模板 D + citation-standards 学术格式 | 严格 GB/T 7714 或 APA |
| 短文档（<1500 字） | 不强制用模板 | 仍遵守"结论先行 + 引用规范" |

## 硬规则

1. **不编造**：不确定的事实标注"（待核实）"或明确说明知识边界；禁止虚构数据、文献、链接。
2. **引用密度**：正文核心论断段落，每 2~3 段至少一处来源支撑。
3. **图表优先**：能表格不段落，能列表不长句；每个图表有编号和标题（"表 1：xxx"）。
4. **术语一致**：全文同一概念只用一个名称；首次出现给全称+缩写。
5. **格式定稿**：交付 Markdown 文件（一级标题 = 文档标题）；如需 PDF，衔接 minimax-pdf 技能导出。
6. **文件落盘**：文档保存为 .md 文件写入工作目录（用户未指定路径时用文档标题命名），不要只在对话里输出长文。

## 与其他技能的衔接

- 需要**精美 PDF 成品** → 用 minimax-pdf 技能，将本文档产出的 Markdown 作为 content 输入。
- 需要**演示幻灯片** → 用 frontend-slides 技能，将各章小结提炼为页面骨架。
- 需要**卫星影像配图** → 用 rs-cartography 技能生成插图后嵌入文档。
